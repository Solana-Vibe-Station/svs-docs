## Cloud Platform Support Tickets

**For technical issues and account-specific problems**

1. Log into [https://cloud.solanavibestation.com](https://cloud.solanavibestation.com)
2. Navigate to **Support** > **Create Ticket**
3. Fill in your issue details:
   - **Title** - Brief description
   - **Category** - Performance, connectivity, billing, etc.
   - **Description** - Detailed explanation
   - **Attachments** - Logs, configs, screenshots
   - **Priority** - Low, Medium, High, or Critical

### Ticket Response Times

- **Critical** - 1 hour
- **High** - 4 hours
- **Medium** - 24 hours
- **Low** - 48 hours

### What to Include in Support Tickets

For fastest resolution, provide:
- Error messages or log excerpts
- Steps to reproduce the issue
- Your service tier
- What you've already tried
- Affected system/service name
- Timestamp when issue occurred

**Example:**
```
Title: gRPC connection timeout from office network

Description:
Getting "connection refused" errors when connecting to gRPC
endpoint from office. Works fine from home network.

Endpoint: grpc.solanavibestation.com:443
Office IP: 203.0.113.45
Error: "connection refused" after 30 seconds

Whitelist status: IP is whitelisted
Firewall: Allows outbound HTTPS
Steps taken: Restarted client, tested with different machine

This started happening today at approximately 2:00 PM ET.
```

## Security Issues

Found a security vulnerability?

**Do not post publicly.** Instead:

1. **Email the security team**: security@solanavibestation.com
2. **DM on Discord**: @security-team
3. **Include details**: Description, affected systems, severity
4. **Allow time**: We'll respond within 24 hours

### What We Need

- Clear description of the vulnerability
- Steps to reproduce
- Potential impact
- Suggested fix (if you have one)
- Your contact information

### Responsible Disclosure

We appreciate responsible vulnerability reporting:
- Give us time to develop a fix before public disclosure
- Don't test on production systems without permission
- Don't share vulnerability details publicly
- We'll credit you in our security advisory

Thank you for helping keep SVS secure!

## Reporting Issues

### Bug Reports

If you find a bug:

1. **Verify it's reproducible** - Test multiple times
2. **Check documentation** - Ensure it's not expected behavior
3. **Search for duplicates** - Check Discord and existing tickets
4. **Report with details**:
   - Exact steps to reproduce
   - Expected vs actual behavior
   - Error messages and logs
   - Your environment (OS, version, etc.)

### Feature Requests

Have an idea for improvement?

1. **Post in Discord** #feature-requests first
2. **Gauge community interest** - See if others want it too
3. **Provide context**:
   - What problem does it solve?
   - Who would benefit?
   - How would it work?

## Best Practices for Support

### Before Contacting Support

1. Check this documentation
2. Search Discord history for similar issues
3. Review the FAQ
4. Try basic troubleshooting steps
5. Collect relevant information

### When Contacting Support

1. **Be specific** - Provide exact error messages
2. **Be reproducible** - Include step-by-step instructions
3. **Provide context** - Service tier, timeline, affected systems
4. **Share logs** - Include relevant error logs
5. **Be patient** - We're working hard to help!

### Getting Faster Responses

- Post in Discord for urgent issues
- Provide detailed information upfront
- Include error messages and logs
- Describe what you've already tried
- Be clear about the priority/impact
